## 001 · 만들 물건의 형태 — Electron MVP

**정한 것**: Electron으로 MVP를 만든다.

**왜**: 차별점이 주소 표시줄인데, 주소 표시줄을 바꿀 수 있는 형태가 몇 개 없다.
확장 프로그램으로는 불가능하고(브라우저 본체가 그리는 UI), 포크는 착수 비용이 크다.
Electron은 착수가 가장 빠르고, 창 UI 전체를 우리가 그린다.

**같이 받아들인 것** — MVP에 없는 것들:
- 비밀번호 저장·자동완성
- 확장 / 광고 차단
- Widevine (넷플릭스·왓챠 재생 안 됨)
- 동기화, 기본 브라우저 등록

즉 MVP는 **주력 브라우저가 아니라 검증용**이다. 이 전제가 흔들리면 형태부터 다시 봐야 한다.

**검토했지만 안 고른 것**:
- 확장 프로그램 — 주소 표시줄 교체 불가. 만들면 브라우저가 아니라 런처가 된다.
- 파이어폭스 포크 — 주소창이 JS(`browser/components/urlbar/`)라 수정이 쉽고 비번·확장·Widevine이 공짜로 따라오지만, 첫 빌드 환경 잡는 진입이 험하다.
- 크로미움 포크 — 빌드 수 시간, 고사양 머신, 상시 인력. 소규모 착수에 안 맞는다.

## 002 · 안정 상태 UI — F11 완전 몰입 (확정)

**정한 것**: 브라우저의 기본(平時) 상태는 F11 전체화면과 동일하다. 탭 스트립, 주소창,
뒤로가기 버튼, 로딩바 등 상시 떠 있는 UI 요소가 하나도 없다. 화면은 항상 페이지 콘텐츠뿐이다.
조작이 필요할 때만 그 위에 소환해서 쓴다.

**의미**: 지금까지의 방향("주소창을 더 똑똑하게 만든다")에서 한 단계 더 간다.
명령 바는 이제 "개선된 주소창"이 아니라 **유일한 조작 수단**이다. 상시 UI가 없으니
지금까지 상시로 떠 있던 것들(탭 스트립, 주소 표시줄, 뒤로/앞으로 버튼, 로딩 인디케이터)을
전부 "평소엔 없다가 필요할 때만 나타나는 것"으로 다시 설계해야 한다.

**원칙**: 평소엔 0, 부를 때만 존재한다. 이벤트가 있을 때만 나타나고, 끝나면 사라진다.

---

### 002-1 · 소환 방법 (제안, 미확정)

단축키(`Ctrl`/`⌘`+`L`)만 사용. 화면 가장자리로 마우스를 미는 방식은 트랙패드에서
실수로 자주 터져서 채택하지 않는 게 좋다고 본다 — 상시 UI를 없앤 의미가 실수 트리거로
희석된다.

### 002-2 · 위치·보안 인지 (제안, 미확정)

완전히 아무 표시가 없으면 두 가지 위험: 피싱 방어 수단 없음, 방향 감각 상실.
**페이지 이동 직후 1~2초만 호스트명이 화면 위쪽에 떴다가 사라지는 방식**을 제안한다.
평소엔 화면이 100% 콘텐츠, "새 곳에 도착한 순간"에만 이벤트성으로 알려준다.

### 002-3 · 탭 개념 (제안, 미확정)

별도의 탭 스트립을 만들지 않는다. 탭은 데이터로만 존재하고, 접근은 전부 명령 바의
`@탭` 범위 · `switch-tab` 액션을 통해서만 이루어진다. (`src/core/rank.js`,
`src/core/registry.js`에 이미 있는 구조와 그대로 맞아떨어진다.)

### 002-4 · 뒤로/앞으로 (제안, 미확정)

버튼 없음. `Alt`+`←`/`→` 또는 트랙패드 스와이프 제스처로만.

### 002-5 · 로딩 표시 (제안, 미확정)

화면 맨 위 얇은 진행 선. 로딩 중에만 나타나고 끝나면 사라짐.

### 002-6 · 권한 요청·다운로드 알림 (제안, 미확정)

상시 UI가 아니라 이벤트 발생 시에만 뜨는 팝업. 나머지 이벤트성 UI(호스트명 토스트,
로딩 선)와 같은 시각 언어를 쓴다.
